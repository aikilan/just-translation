# 两处 P1 死锁修复验证

日期：2026-09-15。对应 [Review 结论](findings.md)。

## 修复

- 候选解析返回时，如果原文已失效，清除该原文对应的 queued 记录及旧渲染引用，释放可视区完成条件。原有 stale 重扫随后重新翻译最新文本。不会删除同一元素上已经建立的新原文记录。
- 屏外放行按具体 DOM 节点是否处于可视区判断，屏外同文副本不再参与可视区渲染完成条件。在途请求、长文本分片及当前可视节点仍按原规则等待。
- 消除导致完成循环无法推进的两个来源，未增加轮询、超时重试或额外调度状态。

## 测试

先加入正式测试并确认 7 项失败，再修改实现。回归测试位于 `src/content/controller-optimizations.test.ts`。

1. 动态翻译开启/关闭 × 候选 cache/miss：解析期间修改可视原文，最终更新后的原文和背景正文均翻译完成，不展示过期缓存。
2. 可视 B 与屏外 B 同文，屏外 B 前还有延期 A：分别验证网络成功、缓存命中和最终失败，全部能结束；同文只请求一次，屏外 A 正常处理，无残留 pending。

测试保留第 50 次 idle 等待时的保护性停止，避免回归后的微任务忙循环阻塞测试进程。修复后的用例均不触发保护。

最终 `pnpm check`：38 个测试文件、362 项测试全部通过，ESLint、TypeScript、Vite 构建和 Service Worker 构建校验通过。

## 浏览器

隔离 Chromium 加载本次生产构建，使用本地服务提供延迟 3 秒的 HTTP/SSE 响应，实际验证「屏外 A、屏外 B、可视 B」场景。

- 首先只请求可视 B，之后继续请求屏外 A。
- 三个节点全部显示结果：`translated=3,failed=0,total=3,phase=complete`。
- 共 2 个请求，无重复、无取消、无页面错误。
