# 全文完整翻译：实现与验收

2026-09-14。基于 `main` 的 `d7e5ef0801fdd54364da7d79bfff37cfdb96c7d6` 实现；保留既有 UI、普通翻译、权限、依赖和存储结构。构建产物在项目根目录 `dist/`。

## 最终行为

右键新增「全文完整翻译（保留上下文）」。右击链接或选中文字仍采集所在页面已经加载的完整正文，不滚动、不翻页、不请求链接目标。按照 DOM 顺序保留每个段落的位置、重复文字、混合语言和完整长段落；保护片段仅传不含原值的标记。

全文一次请求、一次可见提交：不访问段落缓存，不进入分段调度或自动重试。所有 ID、译文和保护标记完整，且 SSE 正常结束后，才分帧准备并统一揭示结果。正文快照在发送前、回填前和提交前复核；校验遍历期间发生变化会重新检查稳定性。取消、正文变化、缺段或协议错误均不留下部分译文。

全文任务使用独立模块，复用现有正文采集、DOM 保护与恢复、分帧回填、后台配置快照、文档身份验证和请求限流。HTTP 的 120 秒计时从队列准入开始；全文单独使用 1 MiB 请求体、16 MiB SSE、1 Mi 字符事件、2 Mi 字符 JSON 上限。普通模式的额度和一次自动重试策略不变。

弹窗显示收集、请求和回填阶段。停止或失败后的重试重新提交全文；重新应用配置时保留全文模式。完成后不自动补译动态内容。网页只显示一个轻量加载或重试入口；错误详情留在扩展界面。首个阅读单元即使是大标题，全文失败提示也保持 14px 普通字重。

## 自动检查

先编写失败用例，再实现功能和修复。最终 `pnpm check` 通过 **37 个测试文件、313 项测试**，同时通过 ESLint、TypeScript、Vite 构建和扩展入口校验。

- HTTP / SSE：完整有序输入、重复与长段落、等待正常结束、缺项、空值、重复和未知 ID、标记损坏、上下文不足、输出截断、异常 EOF，以及全部独立大小限制。
- 内容生命周期：重复启动、原文保留、整体回填、DOM 增删改序、保护文本变化、校验中插入新段落、回填时取消、旧响应、设置变化、普通模式切换、首次 raw prose 的重试位置和排除站点。
- 后台：模式隔离、全篇不发布部分事件、不访问普通缓存接口、取消预检与导航请求、120 秒 HTTP 超时且不自动重试。
- 弹窗：收集／请求／回填状态、停止／失败／完成后的全文重试命令，并回归原有保存和普通翻译交互。

另外用强制分帧复现并修正了普通翻译旧测试的批次关联假设，避免机器负载改变采集切片后产生误报；生产调度行为未因此修改。

## 同时修复的保存误报

首次真实验收复现了「设置写入后回读不一致」：值已经写入，但传入配置与标准化回读的属性顺序不同，直接比较 JSON 字符串导致误报。新增测试先证明不同键顺序失败，再将预期值也转为相同标准结构后比较；真正的字段丢失或变化仍然报错。在隔离扩展设置页实际填写并点击保存，确认显示「已保存」。这与旧 Service Worker 返回 null 的既有问题不同，没有增加兼容消息或直接写入的降级路径。

## 复验与使用

1. 执行 `pnpm check`，启动 `node scripts/browser-fixture-server.mjs`，记下它打印的本地端口。
2. 用独立 Chromium 配置加载 `dist`，在设置页保存模拟 API 地址 `http://127.0.0.1:端口/v1` 和任意测试模型。
3. 打开服务的 `/article`。扩展页面设置为仅译文，在原生右键菜单触发全文翻译。可通过 `/scenario?mode=stream`、`partial`、`slow` 切换并重置模拟服务状态，读取 `/stats` 验证请求与中止数。追加重复、长段落、中文、屏幕外正文和动态段落可复核上表。
4. 更新现有已解压扩展时，先保留未保存草稿，到扩展管理页重新加载「只是翻译」，再刷新需要翻译的网页。

模拟 API 仅验证上下文传输、协议、生命周期和渲染，不证明真实 AI 的语义质量。跨段指代与术语的一致性仍需用实际模型另行评估；本次没有进行真实服务商调用。
