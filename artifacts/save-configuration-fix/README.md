# 保存配置空响应修复

2026-09-11。在隔离 Chromium 中复现并修复截图中的 `Cannot read properties of null (reading 'ok')`。

## 复现结果

1. 从 `f940d3265f3915c2310324dd56a555db18d1c6e2` 构建旧扩展并加载。
2. 用新构建覆盖扩展文件，仅刷新设置页，保持旧后台运行。
3. 新设置页发送 `SAVE_TRANSLATION_PROFILE`；旧后台仅支持原来的保存命令，未匹配分支返回 `undefined`，浏览器将空回包交给调用方为 `null`。
4. 设置页访问 `response.ok`，出现与用户截图完全一致的错误，存储中的模型仍为空。

这是在隔离环境确认的触发条件；未直接读取用户浏览器当前运行的后台版本。连接测试直接访问 API，不经过保存命令，因此测试通过不能证明保存链路可用。

## 修复和恢复

- 消息边界检查空值及无效的结果结构，显示保留草稿和重新加载扩展的明确说明。
- 后台对未知命令返回明确错误，避免再次产生空回包。
- 保存失败时保留字段、维持未保存状态，不直接写存储，不切换到旧保存协议。
- 更新安装说明：先保留未保存内容，到 `chrome://extensions` 点击「只是翻译」的重新加载，再重新打开设置页填写并保存。

已在隔离浏览器的扩展管理页实际点击重新加载，然后重新打开设置页验证：`storedModel = fixture-save-model`、`configured = true`，界面显示“已保存”。该验收只保存合成配置，没有调用外部 AI 接口。
