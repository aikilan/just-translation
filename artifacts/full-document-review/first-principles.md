# 全文翻译问题：第一性原理复核与修复边界

2026-09-14。依据用户调用的 first-principles-analysis 技能重新核对上一轮四项发现。本轮只补充分析和测试证据，没有修改业务实现。

**结论：前三项行为问题成立，第四项属于低优先级的异常输出校验缺口。四个现象对应三处修复：自动启动资格、正文单元复核、唯一响应校验。**

## 必须成立的条件

显示整篇译文时，应同时满足以下条件：

| 条件 | 需要证明的事实 | 当前问题 |
| --- | --- | --- |
| 操作仍有效 | 当前任务来自仍然有效的用户操作；旧的自动启动不能在用户停止或恢复后创建新任务 | 自动启动只等待设置，不记录其启动资格是否已失效 |
| 正文仍匹配 | 当前文档中的有序阅读单元，与发送请求时的单元一一对应；包括位置、边界、原文及本地保护内容 | 全 body 的物理变化被过度解释；已有 source 又跳过了真实子树采集 |
| 响应唯一且完整 | 唯一的最终 translations 数组与输入 ID 一一对应，译文和标记有效，传输正常结束 | 累计回调结果可能来自随后被重复字段覆盖的数组 |

不要求整个网页停止变化，也不要求原始 HTML 字节不变。导航动画和无意义的 inline 包装可以改变 DOM，而不改变需要翻译的正文单元。反过来，平铺文字相同，也不足以证明段落边界没有变化。

## 四项发现的真实性与准确边界

1. **正文外动画导致失败：成立。** 判断应取决于正文采集结果，当前实现却要求连续扫描期间整个 body 没有相关物理 mutation。上一轮浏览器对照已证明：相同 606 单元正文，导航动画开启时失败，停止后完成。本轮重跑行为复现仍失败。这里证明的是快照误判，不是 API 失败。
2. **自动翻译覆盖用户任务：成立。** 本轮使用实际 auto-start 默认消息路径补测：手动全文操作刚开始、自己的设置预检还未完成，旧自动设置响应就能将它替换为分段任务。无需等待全文 HTTP 发出才会触发。另一个反例是用户已明确恢复原文，旧自动响应仍会开始新的分段翻译。
3. **段落边界变化漏检：成立，但需要限定影响。** 复现中原文字没有缺失，不能由此推断 AI 漏收原文或必然产生错误语义。已证明的缺陷是使用过时的阅读单元边界回填：现有 3 段按旧的 2 单元展示，在仅译文模式下隐藏新的原文排版。同样文字只加一个普通 span 的对照测试则正常完成，因此修复不能把任意 innerHTML 变化都当成失败。
4. **重复 translations 字段被接受：成立，维持 P3。** 本轮确认正常空数组会被拒绝，两个串接根对象也会被拒绝。问题仅在根对象重复字段：库先发出第一份数组的 item，再发出第二份空数组，最终根对象为 `{translations:[]}`，累计结果仍保留第一份数据。这应归为异常响应的歧义处理缺口，不代表一般缺段检测失效。

## 修复一：让待执行的自动启动可以失效

修改位置集中在 `src/content/content-script.ts` 与 `src/content/auto-start.ts`。

内容脚本拥有“这次页面启动时的自动翻译”生命周期，可以用原生 AbortController 表示它的资格。用户执行开始、全文开始、重新翻译、停止、恢复或切换等页面任务命令时，以及 pagehide 时，使尚未执行的自动启动失效。自动设置读取返回后先检查该资格，再同步进入任务启动。

控制器的显式 `start()` 继续表达用户选择普通模式；它本来就应该允许从全文切换到分段。修复应发生在迟到自动行为进入控制器之前。

**仅判断 `phase === 'idle'` 无法修复。** “从未启动”与“用户刚恢复原文”都表现为 idle。本轮新增恢复反例已经证明状态名称不能代替用户操作的先后关系。当前任务的 AbortController 也不能单独解决：它只能取消已有任务，无法阻止旧自动流程稍后创建另一个任务。

先写测试覆盖：自动响应迟到于全文开始、停止和恢复；全文预检尚未结束；没有用户操作时仍正常自动启动；显式切回普通模式仍然有效；pagehide 后不再开始旧自动任务。

## 修复二：初次采集与复核使用同一套正文单元规则

修改位置集中在 `src/content/dom-translator.ts` 与 `src/content/full-document-task.ts`。这处同时解决第一项与第三项。

建议按以下边界实现：

1. 复核读取真实原文子树，把扩展的 source-content 包装视为透明容器，并排除扩展译文/反馈；原有 source 标记不再直接证明这个元素仍是一个阅读单元。
2. 复核使用与初次采集相同的正文范围、段落边界、可见性、布局风险和排除规则。比对有序单元、对应的原始位置、源文本及本地保护内容。初次采集需要的可恢复锚点与复核逻辑分开，复核不应再写入宿主 DOM。
3. MutationObserver 用来标出需要重新检查的位置，实际阅读单元是否变化决定结果是否失效。不要以整个 body 的静默作为成功条件，也不要靠增加扫描次数掩盖误判。
4. 分帧扫描期间发生在已扫描分支的变化仍须复核；准备回填后也要再次处理这些变化。最终资格检查与可见提交之间不再让出执行权，避免留下新的检查—提交间隙。

**范围不能简单收缩成“只观察当前 main”。** 新增 main/article、移除旧正文、祖先隐藏状态变化，甚至范围外的 class 通过 CSS 影响正文采集资格，都可能改变正文单元。对于不能证明局部无关的变化，需要重新检查正文范围或采集资格。实现时应先解决这些测试，再决定局部复核的数据结构；不应先引入通用 DOM 依赖图或另一套不一致的正文识别器。

先写成对测试：

| 应允许完成 | 应放弃旧结果 |
| --- | --- |
| 排除区域动画持续更新，正文单元相同 | 真实段落增删、换序或文本变化 |
| 原文增加不改变阅读边界的 span | 同样文字被拆成不同的阅读单元 |
| 扩展自己的反馈与包装节点变化 | 已扫描分支插入新正文 |
| 无关属性变化，实际采集资格不变 | 正文范围或可见/排除资格变化 |

这处的实现风险高于另外两处。修复通过标准需要同时包含“无关变化不会误报”和“相关变化不会漏检”，不能只让动画复现转绿。

## 修复三：要求唯一的顶层 translations 字段

修改位置集中在 `src/shared/openai-stream.ts`，由全文入口继续执行 ID、非空文本和保护标记校验。

已检查安装的 `@streamparser/json`：当前配置本身订阅了 `$.translations` 的完整 value 回调。对于复现输入，它依次发出第一份数组、第二份数组和最终根对象。因此可以在顶层 translations 回调处计数并校验数组类型；第二次出现立即拒绝，不需要自己解析 JSON 字符串，也不需要再增加依赖。

这是应用协议的唯一字段约束。保留现有缺项、未知/重复 ID、截断、正常结束、大小上限和取消校验。分别验证正常单数组通过、单空数组失败、重复字段失败、不同 SSE 分片位置不影响结论；普通翻译的已有流式结果与重试行为也需要回归。
