# 只是翻译

一个本地优先的 Chrome / Edge 网页双语翻译扩展。它只调用你自己配置的 OpenAI-compatible Chat Completions API，不包含任何中转翻译服务。

## 现有能力

- 将译文展示在原文段落下方；确认缓存未命中、请求入队后显示 spinner
- 在“原文 + 译文”和“仅译文”之间切换
- 处理标题、段落、列表、引用和表格单元格
- 正文优先采集：优先 `main` / `article`，跳过导航、网站页眉页脚、侧栏、广告和表单，保留文章 header 内的标题及 flex 中的阅读文本
- 段落内代码和明确标记不翻译的片段使用本地占位符保护，实际内容不发送给 AI；返回时校验标记完整性并以纯文本安全恢复
- 文本噪声过滤：不翻译日期、URL、邮箱、单个大写品牌词和泄漏到 DOM 的脚本文本
- 同页相同原文只请求一次，译文同步映射到所有对应节点
- 长文本 Unicode 与占位符安全分段、上下文分组、批量请求和严格的译文 ID 校验；已校验的成功项立即交给有序渲染队列，缺失、空白或保护标记损坏的项独立补译
- AI 小批次：每批最多 4 段，可见区/下一屏/后台字符预算分别为 1200/1800/2400
- 使用 Chat Completions SSE 增量接收：完整 JSON 译文项校验后立即推送，同一长段落的所有分片齐全后才进入现有有序渲染；不展示半句或逐字刷新
- 流式连接中断只重试未成功的 ID，已校验结果不重发、不覆盖；未知/重复 ID 终止当前响应，已独立成功的段落保留，未完成节点提供重试
- 首个批次立即发送；后续不足一批时最多合并等待 20ms，批次装满或采集完成立即发送，减少渐进采集造成的碎片请求
- 页面最多 6 个在途批次；后台按 API origin 统一限制最多 6 路 HTTP 并发、任意一秒最多发起 6 次请求，多个标签页、模型和配置共享额度
- 非可见内容最多占用 5 个页面派发槽，为新视口留出空间；滚动和新出现的可见同文节点会同步提升页面队列与后台未发送批次的优先级，不抢占已发出的 HTTP
- 当前阅读窗口内严格从上到下，下一屏和后台窗口不会被上方慢请求全局锁死
- DOM 按阅读顺序渐进采集，首批最多 4 个节点；后续按最多 24 个节点 / 8ms 遍历预算切片，大段落的行内片段分析也可让出主线程；最多三个未完成候选解析分片并行推进，单片缓存查询不阻挡后续采集
- 连续正文中的行内链接与前后文字共同翻译，不再把链接单独抽走而漏掉周围句子；包含其他阅读块的布局容器不会被合并
- 嵌套段落前后的散落正文用可恢复的独立阅读单元收集，不丢正文、不重复翻译祖先；恢复后仍是原来的链接和文本节点
- 原文、保护标记及主要可见文本样式共享 DOM 分析快照，页面文字/样式变更立即使快照失效；隐藏文字和保护片段不参与主要字体判断
- 译文分片提交，每片最多 4 个节点；先读取原文排版再写入 DOM，片间让出主线程，保持既有阅读窗口顺序
- 目标语言必需文字系统未出现时直接进入翻译候选，省去无意义的统计语言检测；混合文本仍保留原有置信度校验
- 简繁中文转换保留 Hans/Hant 变体；无法确认与目标文字变体一致时交给 AI，不仅凭统计检测结果 `zh` 跳过
- 翻译完成只更新本批节点的展示模式，不反复扫描整页已翻译节点
- 动态新增、移除、显隐和文本变更后只渐进扫描变化子树，不重扫整页；插件渲染和节点重试不再丢弃同一时刻的页面变更
- 动态子树分别等待 800ms 稳定窗口，单节点重试期间继续收集变更，不让不断更新的相邻区域阻挡稳定段落
- 停止请求、恢复原始网页、按站点和翻译配置隔离的 IndexedDB 译文缓存
- 缓存从首次写入起固定保留 72 小时，每三天自动回收过期记录
- 缓存查询使用只读事务，过期删除单独重验；译文展示和页面完成不等待写入，后台会话在有界写入收尾后清理，数据库打开失败不会永久锁死后续读取
- 翻译前后校验原文快照，页面变化时丢弃过期译文并有限重试
- 翻译失败后自动重试一次：HTTP 错误、断流、响应格式/ID 异常、单次请求超时及缺项补译共享同一额度，每批最多两次 HTTP 尝试；只重发未成功的内容，取消或停止不重试
- 自动重试前默认等待 400ms；429 的 Retry-After 同步暂停同 API 主机的排队请求，不截短服务商要求的等待时间
- 可见区、下一屏、后台的每次 HTTP 尝试分别限制为 20/30/60 秒，等待队列不占用 HTTP 超时时间；重试和缺失项补偿同样经过后台限流
- 停止翻译、关闭标签页及页面导航同时取消旧文档的活动和排队请求；会话绑定浏览器文档 ID，同源翻页不会继续占用旧页面的请求槽
- 没有有效原文消费者的本地排队单元不再派发，整批消费者消失时取消后台批次；BFCache 恢复仅重新启动此前已启用翻译的页面
- 自动重试期间保留 spinner，第二次仍失败才在节点原位提示，支持点击或键盘单独重试
- 长节点手动重试仅补失败或尚未发送的分片，成功分片保存在该节点任务进度中；后台配置指纹或原文变化后不复用旧分片，不新增内存译文缓存
- 翻译节点采用互不包含的叶子阅读单元，避免嵌套表格出现重复译文
- 连接测试会验证接口、Chat Completions 响应结构和非回显结果，并展示实际测试译文供人工确认
- 设置由后台统一保存并回传弹窗使用的配置状态
- 设置保存后会从浏览器存储回读并逐字段校验，弹窗会展示配置未生效的具体原因
- 支持保存多个独立 AI 配置，并在弹窗中切换当前使用的配置
- 每个 AI 配置可独立自定义翻译 Prompt；目标语言占位符可用，节点映射与 JSON 返回协议由扩展固定保护
- 支持为精确域名开启自动翻译，进入站点或翻页后无需手动触发
- 站点排除规则，支持精确域名和 `*.example.com`
- 页面右键菜单“使用「只是翻译」翻译此网页”
- `Alt + T` 快捷键
- 浅色/深色外观

## 安装

### 直接加载已构建版本

1. 打开 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions`。
2. 打开“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本项目的 `dist` 目录。
4. 打开扩展设置，新增或编辑 AI 配置，填写 API 地址、API Key、模型和翻译 Prompt，先执行“测试连接”。
5. 打开普通 HTTP/HTTPS 网页，通过扩展弹窗或页面右键菜单开始翻译。

API 地址可以是：

- `https://api.openai.com`
- `https://api.openai.com/v1`
- `https://api.openai.com/v1/chat/completions`

扩展最终都会请求 Chat Completions 端点。
接口必须支持 `stream: true` 并返回 `text/event-stream`；设置页测试连接与正式翻译使用同一解析器。
不支持 SSE 时会按同一流式协议自动重试一次，仍失败则显示错误，不追加非流式请求。SSE 和 JSON 解析均有大小上限，异常流不会无限占用内存。

地址中的查询参数会被保留，例如兼容 Azure 风格网关所需的 `api-version`。携带 API Key
时，远程地址必须使用 HTTPS；仅 `localhost`、`127.0.0.0/8` 和 `[::1]` 允许 HTTP。

“测试连接”由受信任的扩展设置页直接请求用户配置的 API，可在当前
Network 面板查看请求和服务商返回。正式网页翻译仍由扩展后台发起，API Key 不会
进入网页内容脚本。测试成功只代表接口可访问、响应结构可解析且没有原样回显测试文本；
设置页会展示实际测试译文，最终语言和质量由用户据此确认。

自定义翻译 Prompt 支持 `{{targetLanguage}}` 占位符。扩展会在发送前替换为阅读体验中
选择的目标语言，并固定追加网页防注入、请求 ID 和 JSON 响应规则；这些结构协议不会随
用户 Prompt 一起开放，避免译文无法安全映射回对应网页节点。修改 Prompt 会产生新的
IndexedDB 缓存空间，不会继续命中旧指令生成的译文。Prompt 最长 8000 个字符；一个网页
翻译会话开始后会固定本次使用的配置、目标语言和 Prompt，中途修改只对下一次翻译生效，
避免 AI 请求与缓存键使用不同配置。

## 本地开发

需要 Node.js 22.12 或更高版本，项目固定使用 pnpm 10。

```bash
npx -y pnpm@10.34.5 install
npx -y pnpm@10.34.5 test
npx -y pnpm@10.34.5 build
```

完整校验：

```bash
npx -y pnpm@10.34.5 lint
npx -y pnpm@10.34.5 test
npx -y pnpm@10.34.5 build
```

### 性能诊断与浏览器验收

在扩展 Service Worker 的控制台中，对目标网页发送只读诊断命令：

```js
const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });
await chrome.tabs.sendMessage(tab.id, { type: 'GET_PAGE_DIAGNOSTICS' });
```

诊断仅在当前页面会话内聚合阶段耗时：DOM 发现、配置预检、候选/缓存解析、后台排队、HTTP 请求、顺序等待和渲染。
`firstContent` 和 `firstValidSegment` 分别记录每次 HTTP 尝试到首个非空正文增量、首个通过校验的完整分段的时间；两者都不包括排队时间。
每阶段输出次数、累计时间和最大时间，不记录原文、Prompt、API 地址或 Key，不持久化或上传。
并发阶段累计耗时不能直接相加当作整页耗时；`elapsedMs` 在会话完成或停止时固定。
`firstTranslationMs` 是第一条译文实际提交到 DOM 的耗时；`batches` 统计页面派发的逻辑批次数、分片数与原文字符总量，`cacheHitNodes` 统计缓存命中节点。
逻辑批次数不等于 HTTP 次数：后台的自动重试和缺项补译会增加 HTTP 尝试，需结合 `request` 阶段和 Network 判断。

`node scripts/browser-fixture-server.mjs` 启动仅监听 127.0.0.1 的验收服务，输出随机端口。
`/news` 提供 60 条 HN 结构标题，`/article` 覆盖文章标题、flex 和保护片段；`/v1/chat/completions` 为模拟 API。
`/scenario?mode=normal|partial|fail|fail-once|slow|stream|disconnect|json` 切换正常、缺段补译、持续失败、首次失败后成功、慢响应、逐段流式、首批中途断流和不支持 SSE 场景，`/stats` 返回请求计数、并发上限、取消数与模拟请求的 ID。
使用隔离浏览器配置加载 `dist`；验证 HN 站点规则时，将 HN 文档请求映射到 `/news` fixture。
该服务不是真实翻译模型，不能据此声称服务商推理速度提升。

## 架构

```text
src/
├── background/  # 保管密钥、候选解析、IndexedDB 缓存、AI 请求与取消
├── content/     # 识别网页文本、翻译会话和双语 DOM 渲染
├── options/     # API 与阅读偏好设置
├── popup/       # 当前页面翻译控制器
├── shared/      # 配置、消息类型和文本拆批
└── ui/          # 扩展页面的基础样式
```

## 隐私与权限

- API Key 保存在 `chrome.storage.local`。
- 活跃翻译会话的配置快照暂存在 `chrome.storage.session`，页面会话结束、导航或标签页关闭后清理。
- `webNavigation` 仅用于校验当前文档及清理旧页面任务，不记录或上传浏览历史。
- 扩展后台将存储访问限制为 `TRUSTED_CONTEXTS`，网页内容脚本不能读取密钥。
- AI 请求由扩展后台直接发往你配置的地址。
- 译文缓存键使用 SHA-256，不在 IndexedDB 中保存 API Key 或明文原文。
- API 错误信息会截断并移除配置中的 API Key，避免把密钥带到界面或日志。
- 网页文本会发送给该 API 用于翻译；不要在敏感站点上启用，或将它们加入排除列表。

## 当前边界

当前版本专注普通 HTML 网页阅读，暂不处理 PDF、视频字幕、输入框、Shadow DOM 和图片
OCR。为避免破坏交互和布局，表单、导航、代码块、ARIA 控件以及作为翻译候选本身采用
flex/grid 的容器会跳过；容器内部的普通段落仍可翻译。浏览器内置页和扩展商店也禁止内容
脚本注入。

扩展只在网页 `lang` 声明匹配，或较长文本的本地语言判定同时满足高置信度和明显领先幅度时，
才跳过已属于目标语言的内容。短文本、混合语言和不确定结果仍会发送给 AI，优先避免漏翻。
